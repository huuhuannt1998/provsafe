\section{Discussion}
\label{sec:discussion}

\subsection{When Provenance Matters}

On our 212-scenario benchmark, dangerous-action rules suffice for most attacks: Policy-Only achieves 1.72\% ASR because attack tools are syntactically identifiable. The decisive evidence comes from InjecAgent, where Policy-Only reduces ASR to 12.34\% but \emph{still fails on Data Stealing} (21.7\%), while \sys{} achieves 4.22\%. The difference is structural: attacker tools like \texttt{GmailSendEmail} are legitimate tools invoked with attacker-derived arguments. Risk-tier rules catch CRITICAL/HIGH tools but leave MEDIUM-risk exfiltration channels unprotected. Provenance provides the missing \emph{context}---data lineage revealing whether an argument originated from a user command or attacker-controlled content.

\subsection{Structural Isolation vs.\ Embedding Resolution}

CaMeL~\cite{camel2025} and FIDES~\cite{fides2025} adopt \emph{structural isolation}: untrusted data never reaches the planning LLM, so paraphrase evasion is architecturally impossible. This provides strong worst-case guarantees---CaMeL achieves 0\% ASR on AgentDojo---but at a utility cost: CaMeL's task completion ranges from 48\% to 77\% depending on configuration~\cite{opcamel2025,agentarmor2025}, and the approach requires a dual-LLM architecture with custom interpreter.

\sys{} takes a complementary approach: embedding-based resolution traces arguments through LLM paraphrasing \emph{without} restricting data flow. This preserves higher utility (95\% TSR local, 99.5\% GPT-4o-mini) at the cost of weaker worst-case guarantees---our ASR is 1.02\%, not 0\%. The tradeoff is appropriate for deployment contexts where strict isolation is impractical: legacy agent frameworks without dual-LLM support, multi-vendor pipelines, and high-utility applications where 48\% task completion is unacceptable.

We note that the approaches are not mutually exclusive. \sys{}'s sidecar proxy could wrap an isolation-based system, providing embedding resolution as a fallback for data flows that escape structural boundaries.

\subsection{Limitations}

\paragraph{Policy Engineering.}
Crafting policies that balance security and usability requires domain expertise. All false positives stem from overly conservative policy rules, not provenance misclassification---the DAG correctly identifies benign arguments as trusted. Mitigations include policy templates, adaptive policies, and pre-deployment testing frameworks.

\paragraph{Policy-Only vs.\ \sys{}.}
On the 212-scenario benchmark, the difference (1.72\% vs.\ 1.02\%) is not significant after Bonferroni correction ($p_{\text{adj}} = 0.099$). The decisive evidence is InjecAgent: Policy-Only DS attacks remain at 21.7\% while \sys{} reduces to 8.2\% ($p_{\text{adj}} < 0.001$, $h = 0.52$).

\paragraph{Provenance Granularity.}
Provenance is tracked at argument level via the lattice meet, which can be conservative when benign and malicious content co-locate. Fine-grained sub-argument provenance would improve precision but adds complexity.

\paragraph{Semantic Understanding.}
Policies check paths, tool names, and provenance but cannot reason about intent. Integrating LLM-based intent analysis would improve precision but introduces latency and a new attack surface.

\paragraph{Taint Explosion.}
Conservative propagation may label the entire state as untrusted in long conversations. Our benchmark's high TSR indicates manageability for typical workflows (3--5 tool calls), but production agents (10--50+ calls) would need sanitization primitives or taint reset at session boundaries.

\subsection{Why Not Taint Everything?}

Taint-Everything achieves 0\% ASR---a perfect security score---but collapses TSR to 9.00\% (91\% FPR), rendering the agent unusable. The reason is fundamental: agents \emph{must} read untrusted data to function (device states, file contents, calendar events), and blocking every tool call that touches untrusted data blocks virtually all useful operations. \sys{}'s provenance-gated policies provide the granularity that blanket tainting lacks: the same tool call is allowed when arguments trace to trusted user commands and denied when they trace to attacker-controlled content. This 10$\times$ usability improvement at $<$1.1pp marginal security cost validates the core design thesis.

\subsection{Residual Bypasses}

Three modes: \textbf{Encoding obfuscation} (2.78\% category ASR)---our multi-pass decoder achieves 100\% on 36 test vectors; the residual stems from model-level compliance. \textbf{Indirect chaining}---privilege escalation through legitimate intermediate steps; requires tighter scope constraints. \textbf{Confidentiality exfiltration}---InjecAgent DS results (8.2\% ASR-C vs.\ 0\% DH) confirm MEDIUM-risk channels as the primary gap; reclassifying data-export tools as HIGH risk would close it.

\subsection{Deployment}
\label{subsec:deployment}

\sys{} deploys as a sidecar proxy~\cite{sidecarpattern} intercepting tool calls via the OpenAI-compatible function-calling API---no model modification required. Enforcement overhead is $<$5\,ms per tool call (vs.\ 100--2000\,ms LLM inference). YAML policies support version control and CI/CD deployment. The architecture generalizes beyond IoT to enterprise data-loss prevention, healthcare agents, web browsing, and code generation---any domain with mixed-trust tool inputs.

\subsection{Evaluation Limitations}

Our 212-scenario benchmark is author-crafted; we mitigate bias with InjecAgent (1{,}054 independent cases). We use InjecAgent rather than AgentDojo~\cite{agentdojo2024} as our external benchmark because InjecAgent's 63 unseen attacker tools exercise the provenance resolution pipeline more directly than AgentDojo's 35 injection tasks; a direct comparison with structural-isolation approaches on AgentDojo is future work. Model scale spans five vendor families including GPT-4o-mini; larger models are future work. Each repetition uses a unique cryptographic seed; consistent per-rep ASR reflects structural stability. We do not evaluate confirmation fatigue---a user study is essential future work. All experiments use simulated environments with no real-world side effects; attack payloads are never executed against real infrastructure.
