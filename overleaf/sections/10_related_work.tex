\section{Related Work}
\label{sec:related}

\paragraph{Prompt Injection Attacks.}
Perez et al.~\cite{perez2022ignore} first showed LLMs cannot reliably separate instructions from data; Greshake et al.~\cite{greshake2023not} extended this to \emph{indirect} injection via external content. Benchmarks including InjecAgent~\cite{injecagent2024}, AgentDojo~\cite{agentdojo2024}, and CyberSecEval~\cite{cyberseceval2024} provide standardized evaluation, and OWASP~\cite{owasp-llm2025} now ranks prompt injection as the top LLM risk.

\paragraph{Input Filtering and Guardrails.}
Pattern filters (Rebuff~\cite{rebuff-defense}, LLM Guard~\cite{llm-guard}) and learned detectors (PromptGuard~\cite{prompt-guard}) achieve moderate detection rates but cannot distinguish trusted from untrusted arguments without provenance. Production guardrails (NeMo Guardrails~\cite{nemo-guardrails}) operate at the prompt level rather than the tool-call boundary.

\paragraph{Dual-LLM and Instruction Hierarchy.}
Dual-LLM approaches (Robust Prompt~\cite{robust-prompt}, Self-Reminder~\cite{self-reminder}, Dual-Process~\cite{dual-llm-defense}) add cost or require retraining. StruQ~\cite{struq2024} and SecAlign~\cite{secalign2024} require training-time intervention; instruction hierarchy~\cite{instruction-hierarchy2024} requires fine-tuning. All are model-internal and cannot protect already-deployed models; \sys{} enforces provenance externally without model modification.

\paragraph{Output Validation and Sandboxing.}
LangChain Guardrails~\cite{langchain-guardrails} validate tool calls but make context-free decisions; least-privilege sandboxing is too coarse for agents needing conditional access. \sys{}'s provenance-aware policies allow or deny the same tool call depending on argument origin.

\paragraph{LLM Agent Security.}
Tool-augmented LLMs~\cite{schick2023toolformer,talm} and autonomous agents (AutoGPT~\cite{autogpt}) amplify injection risks; InjecAgent~\cite{injecagent2024} reports 24\% vulnerability for GPT-4. ToolEmu~\cite{toolemu2024} emulates tool execution for safety evaluation but provides no runtime enforcement.

\paragraph{Data Provenance and Taint Tracking.}
Why-provenance~\cite{buneman2001provenance}, the W3C PROV-DM standard~\cite{prov-dm}, dynamic taint analysis~\cite{taint-analysis-survey,taintdroid}, and DIFC systems~\cite{difc-survey,flume} provide foundational models. \sys{} adapts why-provenance to LLM agents with three key differences: opaque computation requiring boundary-level tracking, approximate resolution via embeddings for paraphrased content, and nuanced trust policies since agents must read untrusted data to function.

\paragraph{Capability-Based and IoT Security.}
\sys{} adapts capability-based security~\cite{miller2006capability,capsicum} to LLM tool calls and extends context-aware IoT access control (ContextIoT~\cite{jia2017contexiot}, IoTGuard~\cite{iotguard}) with provenance tracking.

\paragraph{Tool-Call-Level Enforcement.}
Invariant~\cite{invariant2024} detects prompt injection at the tool-call level via behavioral invariants but provides detection-only results without provenance. \sys{} provides the complete enforcement pipeline: provenance tracking, policy evaluation, confirmation gating, and audit logging.
