\section{Related Work}
\label{sec:related}

\paragraph{Prompt Injection Attacks.}
Perez et al.~\cite{perez2022ignore} first showed LLMs cannot reliably separate instructions from data; Greshake et al.~\cite{greshake2023not} extended this to \emph{indirect} injection via external content. Tensor Trust~\cite{tensortrust2024} quantified injection robustness through an adversarial game, revealing systematic weaknesses across models. HijackRAG~\cite{hijackrag2025} demonstrates that retrieval-augmented systems are particularly vulnerable when injected content reaches the context window via external documents. Benchmarks including InjecAgent~\cite{injecagent2024}, AgentDojo~\cite{agentdojo2024}, and CyberSecEval~\cite{cyberseceval2024} provide standardized evaluation, and OWASP~\cite{owasp-llm2025} now ranks prompt injection as the top LLM risk.

\paragraph{Input Filtering and Guardrails.}
Pattern filters (Rebuff~\cite{rebuff-defense}, LLM Guard~\cite{llm-guard}) and learned detectors (PromptGuard~\cite{prompt-guard}) achieve moderate detection rates but cannot distinguish trusted from untrusted arguments without provenance. Production guardrails (NeMo Guardrails~\cite{nemo-guardrails}) operate at the prompt level rather than the tool-call boundary.

\paragraph{Dual-LLM and Instruction Hierarchy.}
Dual-LLM approaches (Robust Prompt~\cite{robust-prompt}, Self-Reminder~\cite{self-reminder}, Dual-Process~\cite{dual-llm-defense}) add cost or require retraining. StruQ~\cite{struq2024} and SecAlign~\cite{secalign2024} require training-time intervention; instruction hierarchy~\cite{instruction-hierarchy2024} requires fine-tuning; Jatmo~\cite{jatmo2024} fine-tunes task-specific models to ignore injected instructions but cannot generalize across tool ecosystems. All are model-internal and cannot protect already-deployed models; \sys{} enforces provenance externally without model modification.

\paragraph{Output Validation and Sandboxing.}
LangChain Guardrails~\cite{langchain-guardrails} validate tool calls but make context-free decisions; least-privilege sandboxing is too coarse for agents needing conditional access. \sys{}'s provenance-aware policies allow or deny the same tool call depending on argument origin.

\paragraph{LLM Agent Security.}
Tool-augmented LLMs~\cite{schick2023toolformer,talm} and autonomous agents (AutoGPT~\cite{autogpt}) amplify injection risks; InjecAgent~\cite{injecagent2024} reports 24\% vulnerability for GPT-4. ToolEmu~\cite{toolemu2024} emulates tool execution for safety evaluation but provides no runtime enforcement.

\paragraph{Data Provenance and Taint Tracking.}
Why-provenance~\cite{buneman2001provenance}, the W3C PROV-DM standard~\cite{prov-dm}, dynamic taint analysis~\cite{taint-analysis-survey,taintdroid}, and DIFC systems~\cite{difc-survey,flume} provide foundational models. \sys{} adapts why-provenance to LLM agents with three key differences: opaque computation requiring boundary-level tracking, approximate resolution via embeddings for paraphrased content, and nuanced trust policies since agents must read untrusted data to function.

\paragraph{Capability-Based and IoT Security.}
\sys{} adapts capability-based security~\cite{miller2006capability,capsicum} to LLM tool calls and extends context-aware IoT access control (ContextIoT~\cite{jia2017contexiot}, IoTGuard~\cite{iotguard}) with provenance tracking.

\paragraph{Tool-Call-Level Enforcement.}
Invariant~\cite{invariant2024} enforces formal security rules on agent actions via a domain-specific language, checking policy violations before execution. However, its rules operate on the tool call itself (tool name, arguments) without data-lineage context---it cannot distinguish the \emph{same} tool call originating from a trusted user command versus an attacker-injected payload; the authors do not report ASR on standard injection benchmarks, making direct numerical comparison infeasible. CaMeL~\cite{camel2025} applies causal mediation analysis to identify whether tool-call arguments were influenced by untrusted context but requires per-query causal tracing and does not provide deterministic enforcement. AgentMonitor~\cite{agentmonitor2025} tracks agent actions at runtime but provides monitoring rather than enforcement, alerting operators post-hoc rather than blocking malicious calls in real time. Spotlighting~\cite{spotlighting2024} reduces injection success by 85\% via prompt delimiters but provides no enforcement mechanism and does not handle tool-call arguments. \sys{} adds the missing provenance dimension: the DAG traces each argument to its source, enabling policies that condition on \emph{where arguments came from}, not just what they contain.

\sys{} is, to our knowledge, the first system combining provenance-gated policies with deterministic enforcement at the tool-call boundary. Its REQUIRE\_CONFIRMATION mechanism introduces moderate user burden for high-risk calls with untrusted provenance (5\% FPR in our evaluation), a deliberate tradeoff for provenance-aware security. It is complementary to prompt-level guardrails as a defense-in-depth layer.
