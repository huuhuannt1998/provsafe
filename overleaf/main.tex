\begin{abstract}
Tool-using LLM agents are vulnerable to prompt injection attacks in which adversaries embed malicious instructions in external content that the agent processes alongside legitimate commands. Existing defenses---pattern filtering, dual-LLM architectures, and output validation---lack a fundamental primitive: \emph{data provenance}. Without tracking where each tool-call argument originated, no defense can reliably distinguish a user-initiated operation from an attacker-injected one, particularly when attacker-chosen tools are not syntactically distinguishable from legitimate ones.

We present \sys{}, a provenance-gated capability enforcement framework for tool-using LLM agents, and demonstrate it on IoT and indirect-injection benchmarks. \sys{} maintains a directed acyclic graph grounded in the W3C PROV Data Model, labeling every input with trust annotations from a two-element lattice and propagating trust via the lattice meet operator. An enforcement proxy resolves each argument's provenance through a three-stage pipeline---substring matching, sentence-embedding similarity, and conservative default---then evaluates declarative policies combining capability restrictions, provenance constraints, and scope limitations. We evaluate \sys{} across 200 scenarios (160 attacks, 40 benign) with five LLMs spanning 3B--122B parameters over five repetitions, yielding 20{,}000 statistically independent trials across four defense configurations. \sys{} achieves an attack success rate on integrity/availability violations (ASR-IA) of \textbf{1.09\% $\pm$ 0.36} with \textbf{95.00\% $\pm$ 1.52 task success rate}, a 24$\times$ reduction versus undefended baselines ($p < 0.001$, Cohen's $h > 0.8$, Fisher's exact test with Bonferroni correction). Crucially, on the external InjecAgent benchmark (1{,}054 indirect prompt-injection cases, 63 attacker tools), policy enforcement \emph{without} provenance achieves 22.67\% ASR---no better than no defense---while \sys{} reduces ASR to \textbf{4.12\% $\pm$ 0.5}, confirming that provenance is essential when attacker tools cannot be identified by syntax alone. On a 122B-parameter model, \sys{} achieves 0\% ASR-IA, demonstrating scalability across a 40$\times$ parameter range.
\end{abstract}
