\begin{abstract}
Tool-using LLM agents are vulnerable to prompt injection attacks in which adversaries embed malicious instructions in content the agent processes alongside legitimate commands. Existing defenses lack a fundamental primitive: \emph{data provenance}---without tracking where each tool-call argument originated, no defense can distinguish user-initiated operations from attacker-injected ones.

We present \sys{}, a provenance-gated policy enforcement framework for tool-using LLM agents. \sys{} maintains a W3C PROV-DM--grounded provenance DAG with a two-element trust lattice, resolves each argument's origin through a three-stage pipeline (substring matching, sentence-embedding similarity, conservative default), and evaluates declarative policies at the tool-call boundary. Across 24{,}240 trials (200+ scenarios, five LLMs spanning 3B--122B parameters, five systems, five repetitions), \sys{} achieves \textbf{1.09\% $\pm$ 0.36} attack success rate (ASR-IA) with \textbf{95.00\% $\pm$ 1.52} task success rate---a 24$\times$ reduction versus no defense, while a Taint-Everything baseline achieves 0.00\% ASR but collapses to 9.00\% TSR (unusable). On the external InjecAgent benchmark (1{,}054 cases), policy enforcement \emph{without} provenance achieves 22.67\% ASR---no better than no defense---while \sys{} reduces ASR to \textbf{4.12\%}, confirming provenance is essential when attacker tools are not syntactically distinguishable from legitimate ones.
\end{abstract}
