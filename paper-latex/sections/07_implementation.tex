\section{Implementation}
\label{sec:impl}

We implement \sys{} as an open-source Python framework (5,000+ LOC) comprising a policy engine, provenance tracker, enforcement proxy, benchmark suite, and evaluation framework.

\paragraph{System Architecture.}
The \textbf{policy engine} parses YAML policies (validated via Pydantic schemas) into compiled in-memory decision trees at startup, enabling O(1) rule lookup by tool name with short-circuit condition evaluation.
The \textbf{provenance tracker} maintains the information-flow DAG using NetworkX with on-demand BFS trust propagation and an inverted index for O(1) amortized substring matching.
The \textbf{enforcement proxy} implements the seven-stage workflow (Section~\ref{sec:proxy}) with three defense layers: pre-LLM input screening, argument validation, and policy evaluation. Decision logging uses append-only JSON with SHA-256 hash chaining.

\paragraph{Benchmark Suite.}
The benchmark contains 160 attack scenarios across 8 categories (Direct Injection, Device Name Injection, File Content Injection, Multi-Turn Chaining, Encoding Obfuscation, Role-Play Jailbreak, Confused Deputy, Privilege Escalation) and 40 benign tasks. All 15 mock tools (file system, calendar, notification, email, device control) use deterministic in-memory backends with seeded RNGs (seed 42) for reproducibility. The evaluation framework orchestrates comparative evaluation of four configurations (No Defense, Pattern Filter, Policy-Only, \sys{} Full) and ablation studies.

\paragraph{Policy Configurations.}
Three policies ship with \sys{}: \emph{default} (used in evaluation; 0.16\% ASR, 98.12\% TSR), \emph{permissive} (equivalent to No Defense baseline), and \emph{strict} (near-0\% ASR, $\sim$21\% TSR). Operators customize via YAML; tools register declaratively with name, risk tier, typed schema, and optional scope.

\paragraph{Performance.}
Proxy overhead is sub-millisecond: policy evaluation median 0.06\,ms, provenance queries median 0.82\,ms, argument validation median 0.15\,ms. End-to-end task runtime averages 20.21\,s vs.\ 12.35\,s undefended; the difference is dominated by user confirmation delays, not proxy computation. Memory footprint is $\sim$55\,MB with 1,000 provenance nodes.

\paragraph{Availability.}
Code is released at \texttt{github.com/huuhuannt1998/provsafe} with documentation, policies, the full benchmark suite, and reproducible evaluation scripts. Installation: \texttt{pip install provsafe}.
